# Безопасность и ключи

## Главное правило

**`.env` не коммитится никогда.** В репозитории лежит только `.env.example`
с пустым значением. Реальный ключ живёт локально в `.env` (он уже в `.gitignore`).

```bash
# проверить, что .env не попал в индекс
git status --short | grep -i env
# правильный ответ: только .env.example
```

## Если ключ всё-таки утёк

1. **Сразу отозвать** ключ в кабинете AnyModel и выпустить новый.
2. Новый ключ вписать только в локальный `.env`:
   ```
   ANYMODEL_API_KEY=sk-новый-ключ
   ```
3. Заменить старый ключ в истории git (если репозиторий уже публичный):
   ```bash
   pip install git-filter-repo
   git filter-repo --path .env --invert-paths
   git push --force
   ```
   Проще и надёжнее — считать старый ключ скомпрометированным и отозвать его:
   истории недостаточно, ключ уже мог быть скачан.

## Что нельзя публиковать

- `installer/dist/*.zip` — архив, собранный с флагом `-IncludeEnv`, содержит
  `.env` с ключом. Каталог `installer/dist/` в `.gitignore`.
- Скриншоты с открытым ключом (в кабинете AnyModel ключ виден на экране).
- Логи `server.log` — там могут быть заголовки запросов.

## Публичная демонстрация

Ключ хранится **только на сервере**, в переменной окружения:

```bash
export ANYMODEL_API_KEY=sk-...
python main.py
```

`main.py` читает переменную окружения, `.env` для этого не обязателен.
Для публичного демо ставьте лимиты на ключ в кабинете провайдера и не давайте
прямой доступ к `/api/chat` без ограничения частоты.

## Если ключ уже был в переписке/скриншоте

Считайте его скомпрометированным: выпустите новый, старый отзовите. Это дешевле,
чем разбираться со счётом за токены.
