# Агро-Радар — MVP агрономической платформы (РУСАГРО × Школа 21)

Рабочий прототип по кейсу: единое окно данных → «Светофор рисков» →
ИИ-Агроном, плюс агрономия поля (почва, фазы, севооборот, обработки, индексы)
и мобильное приложение.

Демо-набор: **12 полей в четырёх районах Белгородской области** (Корочанский,
Белгородский, Валуйский, Алексеевский), 1 290 га, демо-дата **20 мая 2026** —
в одном кадре есть только что посеянные поля, растущие и чистое поле под посев.

---

## 1. Быстрый старт

```powershell
cd agrotech
venv\Scripts\activate
python main.py            # → http://127.0.0.1:8000/
```

или двойным кликом **`Start.bat`** (сам создаст venv, поставит зависимости,
сгенерирует данные и обучит модель, если их нет).

Зависимости: `fastapi`, `uvicorn`, `scikit-learn`, `pandas`, `numpy`, `openai`,
`python-dotenv` (`requirements.txt`). LLM-ключ — в `.env` (`ANYMODEL_API_KEY`).

Проверка API (сервер запущен):

```powershell
python tools\smoke_test.py
```

## 2. Что внутри

### Модуль 1. Карта и погода
- 12 полигонов полей с реальными координатами у сёл Белгородской области;
- карта Leaflet — локальная копия (работает без CDN), drill-down по полям;
- погода: Open-Meteo (реальные данные) ↔ детерминированный демо-симулятор
  (в демо-режиме — симулятор на демо-дату, чтобы показ был повторяемым);
- прогноз на 5 дней, текущие температура/влажность/осадки.

### Модуль 2. Светофор рисков
- ML-модель RandomForest: болезни, засуха, вредители (0–100 %);
- светофор поля = худший риск: 🔴 ≥ 70, 🟠 ≥ 40, 🟢 ниже;
- алерты по критичным полям, объяснение в карточке поля.

### Модуль 3. ИИ-Агроном
- LLM с полным контекстом поля: риски, почва NPK, календарь фаз, обработки,
  севооборот, прогноз. Основная модель — `am/nemotron-3-ultra-558b-a55b`,
  фолбэк — `am/nemotron-3.5-lightning-30b-a3b` (Ultra у провайдера периодически
  отвечает 503/429 — тогда автоматически используется фолбэк);
- каждый ответ проверяется: должен быть по-русски, без иероглифов/арабского и
  без английских слов; иначе модель перезапрашивается, а при неудаче отдаётся
  детерминированный ответ из данных;
- промпт запрещает выдумывать препараты: названия и дозировки берутся только из
  блока «Обработки» контекста;
- потоковая выдача через `/api/chat/stream`: ответ печатается плавно, без
  «мыслей» reasoning-модели;
- история чата в localStorage (24 ч), модальное окно, быстрые вопросы;
- HTML-отчёт по полю со всеми блоками.

### Агрономия поля (новое)
- **Почва:** N-NO3, P2O5, K2O, pH, гумус, сера (мг/кг, слой 0–30 см);
  обеспеченность против целевой для культуры, дозы удобрений в л/га и кг/га;
- **Календарь фаз:** 9–11 фаз с датами (посев → всходы → … → уборка),
  статус «пройдена / сейчас / предстоит», дни до уборки;
- **Технологическая карта:** обработка почвы → удобрения → посев → защита →
  уборка, с датами, статусом и стоимостью ₽/га;
- **Севооборот на 7 лет** с обоснованием чередования и чистым паром;
- **Обработки:** что, когда, чем, дозировка, стоимость, план/факт;
- **Индексы вегетации:** NDVI, EVI, SAVI, GNDVI — ряд за сезон и тренд;
- **Экран «Мониторинг»** (вместо «Сравнения»): культура, фаза, дни до
  уборки, NDVI, NPK с узким местом, обработки, следующая культура севооборота;
- **Раздел «Севооборот»**: сетка «поля × 7 лет» с цветами культур, клик по году
  открывает обоснование;
- **Карточка поля — рабочее место с вкладками**: Обзор · Почва · Фазы · Работы ·
  Защита · NDVI · Севооборот (как страница поля в Агромоне).

### Мобильность
- PWA: манифест, service worker, иконки — установка на домашний экран,
  офлайн после первого открытия (localhost/HTTPS);
- Capacitor-каркас для APK/IPA — `mobile/README.md`.

## 4. API

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/meta` | демо-дата, источник погоды, LLM, версия |
| GET | `/api/fields` | поля со светофором (компактно) |
| GET | `/api/fields/state` | состояние всех посевов |
| GET | `/api/rotation` | севооборот всех полей сеткой «поля × 7 лет» |
| GET | `/api/fields/{id}` | полный разбор поля (включая техкарту) |
| GET | `/api/fields/{id}/soil` | почва и дозы удобрений |
| GET | `/api/fields/{id}/rotation` | севооборот 7 лет |
| GET | `/api/fields/{id}/calendar` | календарь фаз |
| GET | `/api/fields/{id}/spraying` | обработки |
| GET | `/api/fields/{id}/vegetation` | NDVI/EVI/SAVI/GNDVI |
| GET | `/api/alerts` | критичные поля |
| GET | `/api/weather-status` | источник погоды |
| POST | `/api/chat` | `{field_id, question}` — ответ одним куском |
| POST | `/api/chat/stream` | тот же ответ, но текст отдаётся по мере готовности (интерфейс печатает его плавно) |
| POST | `/api/report` | `{field_id, chat_history}` → HTML |

Deep-links интерфейса: `#state`, `#map`, `#rotation`, `#field/A-01`.

## 6. Честные ограничения

- **Данные полей синтетические**: координаты у реальных сёл, но границы и
  показатели — демо. Формат совпадает с выгрузкой агросистемы.
- **Модель обучена на синтетических метках** по экспертной логике; качество на
  реальной истории РУСАГРО не заявляется.
- **Индексы вегетации — модельный ряд** по NDVI поля, а не снимки Sentinel-2;
  абсолютные значения условны, тренд устойчив (`docs/agronomy.md`).
- **Погода в демо-режиме — симулятор** на демо-дату; реальные данные — при
  `demo_mode=false` (Open-Meteo).
- **APK/IPA не собраны**: на машине нет Android SDK/JDK 17 и macOS; PWA и
  каркас Capacitor готовы.
- **Один сервер, одна машина**: нет БД и очередей; масштабирование — отдельная
  задача.

## 7. Проверки и оптимизации

- `pyflakes` — без замечаний; AST-проверка модулей и `node --check` для JS;
- `tools/smoke_test.py` — **39 проверок**, включая живой чат (`llm=True`);
- LLM-запрос выполняется в threadpool: пока ИИ думает 30–40 с, `/api/alerts`
  и статика отвечают за единицы миллисекунд (проверено: 2 мс);
- модель рисков загружается по пути рядом с `main.py`, а не по текущему каталогу;
- демо-прогноз погоды использует стабильный seed — одинаков после перезапуска;
- чат-рендер: списки, заголовки, таблицы-карточки, лимит истории 40 сообщений.

## 10. Публикация на GitHub

Ключ AnyModel хранится только в локальном `.env`, который исключён через
`.gitignore`. В репозиторий попадает лишь `.env.example` с заглушкой.

```powershell
cd agrotech\agrotech
git init
git add .
git status --short          # проверить: .env в списке быть не должно
git commit -m "Агро-Радар: MVP агрономической платформы"
git branch -M main
git remote add origin https://github.com/<user>/<repo>.git
git push -u origin main
```

Проверка перед первым пушем:

```powershell
git ls-files | Select-String -Pattern "^\.env$"      # пусто — хорошо
git grep -n "sk-" -- . ':!.env.example'              # пусто — хорошо
```

После создания репозитория включите в GitHub:
**Settings → Code security → Secret scanning** и **Push protection** —
GitHub будет блокировать пуш с ключом ещё до публикации.

Что публиковать в **Releases**:

- ✅ архив, собранный **без** ключа: `installer\build.ps1` (по умолчанию);
- ❌ архив с `-IncludeEnv` — только лично куратору, не в публичный релиз.

Если ключ уже засветился (скриншот, переписка, старый коммит) — отзовите его
в кабинете AnyModel и выпустите новый: подробности в `SECURITY.md`.
